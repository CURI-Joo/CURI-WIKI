# SOP: AI 세션 기반 위키 자동 작성

> 목적: 개발자가 작업 종료 후 AI에게 한 문장으로 요청해 개인 계정으로 위키 Draft를 자동 생성한다.

## 1) 표준 사용자 시나리오

1. 개발자가 AI 세션에서 아래처럼 요청한다.
   - `오늘 작업 위키로 써줘. 링크: https://<curi-wiki-domain>`
2. AI가 CURI Wiki 페이지를 연다.
3. 로그인 세션이 없으면 AI가 "로그인 해주세요"를 안내한다.
4. 개발자가 구글 로그인(본인 계정) 완료한다.
5. AI가 로그인 확인 후 작업 내용을 구조화한다.
6. AI가 위키에 Draft 문서를 작성한다.
7. AI가 작성 완료 링크(수정/보기)와 요약을 전달한다.

---

## 2) 운영 규칙 (필수)

- 기본 저장 상태는 항상 `Draft`
- 자동 `Published` 금지 (사람 검토 후 발행)
- 작성자는 반드시 로그인한 본인 계정
- 민감정보(토큰/비밀번호/개인정보/고객데이터) 자동 마스킹
- 문서 하단에 출처 링크(PR/커밋/이슈) 첨부

---

## 3) 문서 템플릿(고정 섹션)

- 작업 요약
- 변경 사항
- 테스트
- 영향 범위
- 롤백 계획
- 후속 작업
- 참고 링크

---

## 4) AI 응답 표준 문구

### 로그인 필요 시
`로그인이 필요합니다. 새 브라우저에서 CURI Wiki를 열었습니다. 로그인 완료 후 알려주세요.`

### 작성 완료 시
`Draft 문서 작성 완료했습니다. 아래 링크에서 검토 후 발행해주세요.`
- 수정 링크: `/documents/<slug>/edit`
- 보기 링크: `/documents/<slug>`

### 실패 시
`자동 작성에 실패했습니다. 실패 지점: <인증/네트워크/권한/저장>. 재시도 또는 수동 작성 링크를 안내합니다.`

---

## 5) 실패 대응 Runbook

### A. 로그인 확인 실패
- 증상: 로그인 후에도 작성 권한 없음
- 확인: 계정 상태 `approved` 여부
- 조치: 관리자 승인 후 재시도

### B. 저장 실패(500)
- 증상: Draft 생성 API 실패
- 확인: 서버 로그의 `create_failed`/DB 오류 메시지
- 조치: API 재시도, 임시로 수동 작성 경로 안내

### C. 권한 실패(403)
- 증상: API에서 forbidden
- 확인: profile status/role
- 조치: 승인 상태 점검, Secret 카테고리 접근 권한 점검

### D. 네트워크 실패
- 증상: network_error
- 조치: 1회 자동 재시도 후 실패 시 수동 링크 제공
