# CURI Wiki Design System Notes

문서 작성/수정 화면에서 사용하는 최신 UI 규칙입니다.

## Document Editor (2026-09 업데이트)

- 편집 탭은 `간편 편집`, `Markdown` 2개만 유지합니다.
- `미리보기` 탭은 제거되었고, `간편 편집`이 읽기 중심 화면 역할을 겸합니다.
- `영상` 버튼으로 MP4·WebM·MOV(파일당 최대 50MB)를 본문에 삽입합니다. 간편 편집과 Markdown 모두 지원하며, 파일 버튼·드래그·붙여넣기로 선택한 영상도 재생 블록으로 삽입합니다.
- 영상은 자동 재생 없이 기본 재생 컨트롤과 전체화면을 제공하고, 처음에는 메타정보만 불러옵니다. 브라우저에서 재생할 수 없는 코덱은 오류 안내와 `원본 열기`를 제공합니다.
- 업로드 진행률을 표시하고 완료 전에는 저장과 편집 모드 전환을 막습니다. 영상 선택 후 Backspace/Delete, 우클릭 메뉴, 편집 화면의 `영상 삭제` 버튼으로 지울 수 있습니다.
- 영상 파일은 서명된 업로드 주소로 비공개 Storage에 직접 전송해 앱 서버의 요청 크기 제한을 피합니다. 완료 시 사용자·문서 권한과 실제 파일 크기/형식을 확인한 뒤 첨부 기록을 생성합니다. 저장 형식은 `[파일명](/api/upload/id/file "curi:video")`이며 임시 로컬 주소는 저장하지 않습니다.
- 공개 일반 문서에 실제 삽입된 영상은 로그인 없이 재생할 수 있습니다. Draft·Secret 및 일반 첨부 링크는 기존 접근 제한을 유지합니다.
- 작성·수정 화면 하단에 별도의 첨부파일 목록을 표시하지 않습니다. 이미지와 파일은 본문 도구 모음에서 삽입하고 본문 안에서 확인합니다.

## Document Drive Shortcut

- 작성·수정 화면의 제목 아래에 선택 입력 항목인 `Google Drive 링크`를 둡니다. Google Drive 폴더·파일 또는 Google Docs의 HTTPS 공유 링크를 붙여넣습니다.
- 링크가 있는 글만 작성자·날짜 정보 영역에서 날짜 오른쪽에 Google Drive 로고와 `Google Drive 바로가기`를 표시하고 새 탭으로 엽니다. 날짜와 버튼은 함께 배치하며 좁은 화면에서는 자연스럽게 줄바꿈합니다. 비워 두면 읽기 화면에 해당 공간을 만들지 않습니다.
- 링크는 Markdown의 예약 헤더 `<!-- curi:drive-url URL -->`와 빈 줄로 저장합니다. 읽기·편집 본문과 요약에서는 분리하며 기존 원문 출처인 `source_url`은 보존합니다.
- MCP `create_document` / `update_document`에서도 `drive_url`을 받습니다. 생략하면 유지하고, `null`이나 빈 문자열이면 제거합니다. 본문만 바꾸는 업데이트에서도 기존 링크를 보존합니다.

## Image and Text Layout

- 본문 이미지를 클릭하거나 키보드 Enter/Space로 선택하면 확대 창을 엽니다. 확대·화면에 맞추기·원본 새 탭·닫기를 제공하고 Escape나 배경 클릭으로 닫습니다.
- 본문에는 최대 1600px WebP 미리보기를 사용하고, 확대할 때 원본을 불러옵니다. 미리보기는 같은 비공개 Storage 버킷에 별도로 저장하며 원본 주소와 Markdown은 유지합니다. 애니메이션과 최적화할 수 없는 형식은 원본으로 표시합니다.
- 공개된 일반 문서에 실제 삽입된 이미지는 로그아웃 상태에서도 표시합니다. 나머지 첨부 이미지는 로그인/문서 권한을 확인합니다. 이미지 응답은 브라우저 개인 캐시에서 5분 동안 재사용하고 사용자 쿠키에 따라 분리합니다. 새로 올린 이미지는 로컬 파일로 즉시 표시합니다.

- `옆글쓰기`는 사진·캡션과 설명을 하나의 두 칸 영역으로 묶습니다. 칸 사이 간격은 24px이며 이미지 칸은 본문 너비의 최대 50%입니다.
- 본문 너비가 560px 이하이면 사진 → 설명 → 다음 본문 순서로 세로 배치합니다.
- 배치 도구는 `옆글쓰기` 토글 하나만 표시합니다. 켜면 사진 옆에 커서를 놓고, 끄면 이미 쓴 옆글을 유지하면서 아래 본문으로 이동합니다. 버튼의 선택 상태는 현재 커서 위치와 일치합니다. 마지막 빈 옆글 문단에서 Enter를 눌러도 아래로 이동합니다.
- `좌우`, `아래에 이어 쓰기` 버튼은 표시하지 않습니다. 사진을 직접 드래그해 좌우로 이동하며, 옆글 사진을 반대편으로 드래그하면 두 칸의 순서가 바뀝니다.
- 읽기와 편집 모두 같은 구조를 사용합니다. 저장은 `:::image-text`와 `:::image-text-end` 사이에 기존 이미지 Markdown과 설명을 보존합니다. 코드 블록 안의 표기는 레이아웃으로 해석하지 않습니다.
- 기존 `|wrap` 이미지는 뒤따르는 설명과 묶되 다음 제목·이미지·표부터는 아래에 표시합니다. 다시 저장하면 종료 경계가 명시됩니다.

## Document Cards

- 홈·전체 글·카테고리 카드에는 제목과 문서 메타정보를 표시하며, 제목 아래 요약문은 표시하지 않습니다.

## Highlight Palette

- 형광펜은 `src/lib/highlight-colors.ts`의 10색을 5열 × 2행으로 표시합니다.
- 색연필로 칠한 모양의 색상 견본과 선택 표시만 노출하고, 색 이름은 접근성용 `aria-label`에 제공합니다. 도구 아이콘도 연필 모양을 사용합니다.
- 본문과 간편 편집의 강조는 가는 결, 약간 비스듬한 가장자리, 옅은 끝부분을 가진 색연필 질감으로 표시합니다. 줄바꿈되는 강조에도 각 줄마다 질감을 적용합니다. SVG 배경 질감만 더해 기본 글자색과 기존 10색 값·저장 형식·실행 취소 동작을 유지합니다.
- CURI 핑크·빨강·주황·민트·회색은 현재 `globals.css`의 브랜드/상태/중립 색상을 흰색 위에 옅게 적용한 톤입니다.
- 기존 10색의 값과 저장 형식을 유지하며, 읽기·간편 편집·Markdown 모드에서 같은 색을 사용합니다.

## Text Colors

- 글자색은 `src/lib/text-colors.ts`의 10색을 5열 × 2행으로 표시합니다. 밝은 본문 배경에서 읽기 쉽도록 형광펜보다 진한 색을 사용합니다.
- 각 색은 해당 색의 `A`와 선택 표시로 보여 주고, 색 이름은 `aria-label`에 제공합니다.
- 텍스트를 선택한 뒤 글자색을 고릅니다. 형광펜·굵게 등과 함께 적용할 수 있으며, 간편 편집·읽기·Markdown 모드 사이에서 보존합니다.
- 저장 구문은 `{{color:blue}}텍스트{{/color}}`입니다. 목차에는 서식 구문 없이 제목만 표시합니다.

## Category Row

- 카테고리 라벨은 영어 `Category`를 사용합니다.
- 카테고리 선택은 브라우저 기본 `<select>` 대신 `src/components/ui/select.tsx`를 사용합니다.
- 라벨과 선택 토글은 한 줄 정렬을 유지합니다.
- 라벨은 별도 작은 박스 형태로 표시합니다.

## Category Actions (Admin)

- 카테고리 추가/삭제 버튼은 정사각형(`h-10 w-10`)을 유지합니다.
- 버튼 테두리는 사용하지 않습니다.
- 배경은 `bg-surface-elevated`, hover는 `bg-surface`를 사용합니다.

## Border/Shape Preference

- 문서 작성 화면에서는 불필요한 외곽선 사용을 줄입니다.
- 입력 컨트롤은 라운드 스타일을 유지하되, 액션 버튼은 과한 둥근 모서리를 피합니다.

## Category Source of Truth

- 좌측 사이드바 기준 카테고리 체계(`Company`, `Projects`, `Guides`, `Secret`)와
  문서 작성 화면의 카테고리 목록은 동일해야 합니다.
- 레거시 카테고리(`cat-curi-ai`, `cat-wame`)는 정규화 매핑으로 처리합니다.
