# CURI Wiki Issue Guide

> CURI Wiki의 ISSUE는 제품에서 발견된 문제와 개선사항을 등록하고, 해결 상태를 팀에서 함께 확인하기 위한 기능입니다.

## Why ISSUE?

Telegram이나 구두로만 이슈를 공유하면 시간이 지나면서

- 누가 수정하고 있는지
- 아직 해결되지 않았는지
- 어떤 이슈가 급한지
- 이전에 같은 문제가 있었는지

확인하기 어려울 수 있습니다.

CURI Wiki의 ISSUE에서는 이슈를 프로젝트별로 기록하고 해결될 때까지 상태를 관리합니다.

## Structure

현재 ISSUE는 Jira처럼 `Project → Issue` 구조입니다.

```text
ISSUE
├─ Admin
├─ Healthcare
└─ Dashboard
```

각 프로젝트 안에서 이슈를 등록하고, 목록을 확인하고, 상세 내용을 볼 수 있습니다.

## 이슈 등록 방법

1. 사이드바에서 **ISSUE**를 클릭합니다.
2. 이슈를 등록할 프로젝트를 선택합니다.
   - Admin
   - Healthcare
   - Dashboard
3. 우측 상단의 **New Issue** 버튼을 클릭합니다.
4. 중요도, 제목, 내용, 담당자, 첨부파일을 입력합니다.
5. **이슈 등록** 버튼을 클릭합니다.

이슈 내용에는 다음 정보를 함께 적어두면 확인이 빠릅니다.

- 문제가 발생한 화면 또는 기능
- 실제로 발생한 문제
- 원래 기대한 동작
- 재현 방법
- 참고할 스크린샷 또는 영상

## 중요도

중요도는 이슈를 얼마나 빠르게 확인해야 하는지 판단하기 위한 기준입니다.

| 중요도 | 의미 | 예시 |
| --- | --- | --- |
| **즉시 수정 필요** | 서비스 사용이 어렵거나 바로 대응이 필요한 문제 | 로그인 실패, 저장 불가, 주요 기능 오류 |
| **차차 수정 필요** | 기능은 사용할 수 있지만 수정이 필요한 문제 | 일부 화면 깨짐, 특정 조건에서 발생하는 오류 |
| **개선 사항** | 오류는 아니지만 더 좋게 만들 수 있는 부분 | 문구 수정, UX 개선, 동작 방식 개선 |

긴급 여부가 애매하다면 우선 현재 업무에 미치는 영향을 기준으로 선택하고, 팀에서 논의하며 조정합니다.

## 상태 흐름

이슈는 아래 순서로 진행됩니다.

```text
이슈 등록 → 해결 중 → 이슈 해결
```

| 상태 | 의미 |
| --- | --- |
| **이슈 등록** | 새로 등록된 상태입니다. 아직 수정 작업이 시작되지 않았습니다. |
| **해결 중** | 담당자가 이슈를 확인하고 수정 또는 확인 작업을 진행 중입니다. |
| **이슈 해결** | 수정 또는 확인이 완료된 상태입니다. |

상태는 순서대로 변경합니다. 같은 문제가 다시 발생하면 기존 이슈를 되돌리기보다 새 이슈로 등록해 기록을 남기는 것이 좋습니다.

## 담당자 지정

이슈를 등록할 때 담당자를 지정할 수 있습니다.

- 담당자는 이슈를 확인하고 해결을 진행할 팀원입니다.
- 담당자를 지정하면 해당 팀원이 어떤 이슈를 맡고 있는지 목록에서 확인하기 쉽습니다.
- 담당자가 아직 명확하지 않다면 미지정으로 등록한 뒤 팀에서 논의해 지정합니다.
- 담당자를 지정한 이슈는 Telegram 알림 설정에 따라 알림이 전송될 수 있습니다.

담당자를 지정했다고 해서 혼자 해결해야 한다는 의미는 아닙니다. 필요한 경우 댓글, Telegram, 회의 등을 통해 함께 확인합니다.

## 이미지/영상 첨부

이슈를 설명하기 어려운 경우 이미지나 영상을 함께 첨부합니다.

### 첨부 방법

- 첨부 영역을 클릭해 파일 선택
- 파일을 첨부 영역으로 드래그 앤 드롭
- 클립보드 이미지를 `Cmd+V`로 붙여넣기

### 첨부 기준

- 화면 깨짐, UI 오류는 스크린샷을 첨부합니다.
- 재현 순서가 중요한 문제는 짧은 영상을 첨부합니다.
- 민감한 정보가 보이는 화면은 필요한 부분만 캡처하거나 가린 뒤 첨부합니다.

### 제한 사항

| 항목 | 제한 |
| --- | --- |
| 최대 파일 수 | 4개 |
| 이미지 크기 | 10MB 이하 |
| 영상 크기 | 50MB 이하 |
| 총 용량 | 100MB 이하 |

## 해결 완료까지의 흐름

1. 이슈를 발견한 팀원이 ISSUE에 등록합니다.
2. 프로젝트, 중요도, 제목, 내용을 입력합니다.
3. 필요하면 담당자와 첨부파일을 함께 등록합니다.
4. 담당자가 이슈를 확인하면 상태를 **해결 중**으로 변경합니다.
5. 수정 또는 확인이 완료되면 상태를 **이슈 해결**로 변경합니다.
6. 같은 문제가 다시 발생하면 새 이슈를 등록하고 이전 이슈 ID를 내용에 남깁니다.

## 작성 예시

```text
프로젝트: Admin
중요도: 차차 수정 필요
제목: 모바일에서 AI Survey 설정 Modal 하단 버튼이 보이지 않음

내용:
Admin > AI Survey 설정 화면에서 모바일 화면으로 접속하면
Modal 하단의 저장 버튼이 화면 밖으로 밀려 클릭하기 어렵습니다.

재현 방법:
1. 모바일 화면 크기로 Admin 접속
2. AI Survey 설정 Modal 열기
3. 하단 저장 버튼 위치 확인

기대 동작:
저장 버튼이 화면 안에서 바로 보여야 합니다.

첨부:
모바일 화면 스크린샷
```

## FAQ

**Q. 이슈를 잘못 등록했어요.**  
A. 이슈 상세 페이지에서 **삭제** 버튼을 눌러 제거할 수 있습니다. 삭제 전 확인창이 표시됩니다.

**Q. 담당자를 꼭 지정해야 하나요?**  
A. 필수는 아닙니다. 담당자가 명확하지 않으면 미지정으로 등록한 뒤 나중에 정해도 됩니다.

**Q. 해결된 이슈와 같은 문제가 다시 발생했어요.**  
A. 새 이슈를 등록하고 내용에 이전 이슈 ID를 함께 적어주세요.

**Q. 이미지나 영상은 언제 첨부하나요?**  
A. 화면 상태, 재현 순서, 오류 메시지를 글로 설명하기 어려울 때 첨부하면 좋습니다.
